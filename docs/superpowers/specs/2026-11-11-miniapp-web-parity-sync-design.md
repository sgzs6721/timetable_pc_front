# 小程序近两日改动同步到 Web 设计

日期：2026-11-11  
仓库：`timetable_pc_front`  
对照基线：Web 上次同步至小程序 `41526f5`；本轮同步小程序至 `b6df7d8`（含 `9807056`、`a3e2456`、`cdd9d46`、`f499e7f`、`b6df7d8`）  
约束：只改 Web 前端；后端与小程序代码不动；移动端专属 UI（自定义导航栏、下拉刷新、Tab 图标）不同步。

## 目标

将小程序近两日机构管理端业务行为对齐到 Web，使同一后端字段与校验在两端一致。

## 方案

采用现有 Web 模块增量对齐：在打卡、课表弹层、客源、课程、工资页面补字段、校验与展示，沿用桌面 Form / Switch / Modal，不抽跨端共享包，不大改课表弹层结构。

## 功能设计

### 1. 课表 `checkInOnly`（仅打卡 / 不计老师课时）

- 在 `Schedule` 与 cell 保存/复制/移动 payload 增加 `checkInOnly?: boolean`。
- 课表格弹层（现有备注区附近）增加开关，文案对齐小程序：「自动打卡时，不计老师课时」。
- 打开已有课时回显 `schedule.checkInOnly`；开关变化计入 dirty，可单独保存。
- 保存、模板版本、实例化、复制路径必须显式发送 `true` 或 `false`，不能因 falsy 被请求清理逻辑丢掉。
- 课时管理列表：无老师且非服务记录时可视同「跳过老师课时」展示；若记录带 `checkInOnly`，展示「仅打卡」标记（对齐 `schedule-manage`）。

### 2. 学员打卡「不计老师课时」

入口：学员详情打卡弹窗、学员列表快捷打卡。

- 增加开关，默认关闭；打开/重置表单时清零。
- 关闭：含课程打卡时仍要求至少 1 位老师，且不超过课程配置上限。
- 打开：允许不选老师；提交时 `coachIds` 为空数组，`coachId` / `coachName` 为空；不校验老师人数。
- 编辑已有打卡：若历史记录无老师，开关默认打开。
- 服务打卡路径不受该开关影响（与小程序一致：服务不走老师课时跳过语义）。

### 3. 课表「本周/所有排课」记录过滤

在 Web cell 弹层加载/展示排课记录时，对齐小程序 `shouldIncludeActionScheduleRecord`：

- `uiChangeStatus === 4`（占用）不展示。
- `uiChangeStatus === 3`（请假）：仅当有 `scheduleDate` 且能匹配到当前仍有效的固定课模板时展示。
- 无 `scheduleDate` 的模板行：仅当匹配当前有效固定课才展示，避免改时段后的历史模板冒充本周排课。
- 匹配模板时排除 `uiChangeStatus` 为 3 或 4 的模板行（改时段后的移除版本不能当有效固定课）。

实现为纯函数（可放在 `schedule-board-helpers` 或独立小模块），对「本周」「所有」两套列表统一过滤。

### 4. 客源校区仅已上线

- 列表筛选校区：只展示 `visibleInList` 为上线的校区（复用现有 campus online 判定，与小程序 `isCampusAvailableInList` 一致）。
- 新建客源：校区选项仅上线校区；若没有可选校区，提示「暂无已上线校区，请先上线校区后再录入」，禁止打开空校区表单。
- 编辑已有客源：校区已锁定时保留原校区选项（即使已下线），新建路径仍只给上线校区。
- `LeadCampus` 类型补充 `visibleInList`。

### 5. 课程管理排除下线校区

- 课程页用于切换/列表的校区数据源始终排除下线校区（对齐小程序 `includeHidden: false`）。
- 当前选中校区若已下线：清空本地选中并走现有无校区/重选逻辑，不继续用隐藏校区 ID 拉课。
- 单校区详情只读态（已有 `visibleInList` 校验）保持不变。

### 6. 工资汇总 `paymentDate`

- 工资汇总人员/校区明细类型增加 `paymentDate?: string`。
- 已发放展示优先用 `paymentDate`，缺省回退现有 `paidTime`（或当前已用展示字段），避免有发放日期却只显示支付时间。

## 非目标

- 不改后端接口、实体、AutoTable。
- 不同步小程序导航栏、下拉刷新、底部 Tab 图标、家长端/营销公开页。
- 不重写课表弹层或打卡弹窗整体布局。

## 错误处理

- 打卡：未开「不计老师课时」且无老师 → 原有拦截文案。
- 客源：无上线校区 → 明确业务错误，不静默空列表。
- 课表保存：`checkInOnly` 与其它 dirty 字段一并提交；失败提示沿用现有 `tell`。

## 测试与文档

- 单测覆盖：`checkInOnly` 写入 payload、打卡 skip 老师提交、排课记录过滤、客源校区过滤、课程校区排除、工资日期优先展示。
- 更新 `docs/miniapp-web-parity.md` 增加「2026-11-11」同步节。
- 验证：`npm test`、`npm run check:parity`、`npm run build`。

## 风险与缓解

- 请求体清理可能丢掉 `checkInOnly: false` → 保存路径显式带布尔值，并加测试断言。
- 排课过滤过严误藏真请假 → 严格按小程序函数语义移植并单测边界（有日期+匹配模板才保留 status=3）。
- 编辑客源时下线校区消失 → 锁定原 `campusId` 时不参与上线过滤。
